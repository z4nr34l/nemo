Starting with **v3.0.0**, NEMO is published as `@zanreal/nemo`.

The API did not change. Same exports, same signatures, same behaviour — only the package name
is different. For most projects this is a two-line migration.

## Automatic migration

A codemod does the whole thing — imports and `package.json` — in one pass:

```bash
npx @zanreal/nemo-codemod
```

Then reinstall so your lockfile picks up the new package:

```bash
npm install
```

Pass `--dry` first if you want to see the changes before they are written. The codemod is an AST
transform, so it only rewrites real module specifiers — mentions of `@rescale/nemo` in comments or
strings are left alone. Full options are in the
[codemod README](https://github.com/zanreal-labs/nemo/tree/main/packages/codemod).

## Manual migration

It is a rename, so doing it by hand is fine too.

<Steps>
  <Step>
    ### Install the new package

    ```package-install
    @zanreal/nemo
    ```

    …and remove the old one:

    ```bash
    npm uninstall @rescale/nemo
    ```

  </Step>
  <Step>
    ### Update your imports

    ```ts title="proxy.ts"
    import { createNEMO } from '@rescale/nemo'; // [!code --]
    import { createNEMO } from '@zanreal/nemo'; // [!code ++]
    ```

    Subpath imports move the same way:

    ```ts
    import { MemoryStorageAdapter } from '@rescale/nemo/storage'; // [!code --]
    import { MemoryStorageAdapter } from '@zanreal/nemo/storage'; // [!code ++]
    ```

  </Step>
</Steps>

That's it. No code changes, no config changes.

## Do I have to migrate right now?

No. `@rescale/nemo` is still published — as of v3.0.0 it is a thin alias that re-exports
`@zanreal/nemo`, so your existing installs keep working and keep receiving upstream fixes
transitively.

It is, however, **deprecated**. `npm install` will print a deprecation notice, and the alias
will eventually stop being published. Treat it as a grace period, not a permanent home.

<Callout type="info">
  Both packages resolve to the same code at runtime, so a dependency tree containing both — for
  example, your app on `@zanreal/nemo` and a library still on `@rescale/nemo` — works correctly.
  You will just have the alias package installed alongside it.
</Callout>

## Why the move

NEMO is now maintained by [ZanReal](https://zanreal.com) as a company project rather than one
person's side project, so the package and the repository moved to the organisation's own scope.
Nothing about the licence (MIT), the maintainers, or the project's direction changes.

[Project stewardship](/docs/2.0/stewardship) has the longer version.

## Still on v1.4?

The [v1.4 documentation](/docs/1.4) continues to describe `@rescale/nemo`, because that version
was only ever published under the old name. Upgrade to v2 first — see the v1.4 docs for the API
differences — then follow this guide.
